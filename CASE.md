# Кейс: агентная фабрика AI-визуала для e-commerce

**Автор:** Виктор Сергеев, AI-визуал (фото и видео для брендов), Ижевск.
**Срок:** 31.10–01.11.2026, три этапа (M1–M3); M4 — ежедневная эксплуатация до конца года.
**Код:** этот репозиторий, 32 теста. Цифры в кейсе — из `results/`, у каждой есть журнал прогона.

## Задача
Я делаю коммерческие карточки и ролики для товаров: кадр с моделью или предметку, плашки, короткий ролик с субтитрами.
Раньше это была цепочка ручных скриптов: Seedream и MiniMax через API, Pillow для плашек, ffmpeg и Remotion для монтажа.
Самое дорогое место — **проверка**: генераторы незаметно портят товар (гвоздик превращается в подвеску, меняются металл,
камень, форма оправы), и каждый кадр я сверял с фото товара глазами.

Цель: превратить цепочку в систему агентов, которая сама генерирует, проверяет, перегенерирует, учится на браке
и даёт цифры по качеству и деньгам.

## Решение

```
YAML-бриф ─► оркестратор ─► агент кадров ─► судья ──reject──► перегенерация с замечанием
   ▲                            ▲            │  └── правило ─► память (следующие прогоны)
   │ factory new                │            ▼ approved
 фото + ТЗ                  правила   карточки · видео ─► судья видео ─► монтаж (Remotion) ─► QC-агент
                                                              журнал: события, $, время, метрики
```

| Требование | Как сделано |
|---|---|
| Spec-driven | Вход — YAML-бриф: черновик собирает `factory new` из фото и ТЗ, бриф проверяется до запуска. Сам проект ведётся по `specs/` с критериями приёмки, у каждого критерия есть тест |
| Оркестрация агентов | Агенты кадров, судьи, карточек, видео, монтажа и QC; параллельно по шотам; бюджет резервируется до каждого платного вызова |
| Проверка результата | Судья — Claude (headless `claude -p`, JSON-схема) с фото товара; зум для мелких объектов; цвет камня — ΔE в Lab; сцена шота; судья видео по кадрам ролика; QC монтажа |
| Память | Отбраковка → правило по тегу товара → в промпт и чек-лист судьи на следующих прогонах |
| Метрики | Каждое решение — событие в журнале; реальные траты по балансу провайдера; `factory weekly` — только live-цифры |

## Цифры

| | Верный вердикт | Брак пойман | Ложный брак |
|---|---|---|---|
| Замер | **97,9 %** | **2/2** | 1/45 |
| Правило двух сигналов, пересчёт тех же ответов | 47/47 | 2/2 | 0/45, 2 кадра человеку |

Модель судьи выбрана замером: на синтетике с известным браком Haiku без фото товара браковал **57 %** хороших кадров,

## Пять находок, которые изменили систему
1. **Судье нужно фото товара.** Без него точность по признакам была 70 %, с фото — 91 % (Haiku), 100 % (Sonnet).
2. **Ложный брак на мелких объектах.** На кадре в полный рост судья «увидел» деталь, которой нет, на серьге в 3 % ширины кадра.
   → Второй проход по увеличенному фрагменту. Зум сам ошибся на другом кадре (тёплый свет сделал серебро «золотым»),
   поэтому пришлось ввести **правило двух сигналов**: брак — только при согласии обоих, спор уходит человеку.
3. **Моя ручная проверка тоже ошибается.** На глаз камень на кадрах «стал оранжевее». Замер ΔE на 6 настоящих фото товара
   показал, что разброс от света — 7–20, у кадров 3–19, сдвига нет. Порог откалиброван по реальным фото, а не на глаз.
4. **Сбой сети не должен стоить денег.** Задача оплачена, ответ не пришёл, прогон упал. → id задачи пишется на диск
   до опроса, POST не повторяется никогда, `--resume` забирает оплаченное. Восстановленный прогон — без второй оплаты.
5. **QC-агент нашёл то, что я бы пропустил в монтаже.** Синтезатор читает «AURA» как «о-о-о»; Piper в каждом дубле звучит иначе
   (WER 0 % и 20 % на одном тексте) — отсюда цикл дублей. Ещё QC нашёл стоп-кадры в старом монтаже. Субтитр поверх плашки
   и фразу через склейку я нашёл глазами и добавил их в QC.

## Как я этим пользуюсь
- Каждый заказ: папка с фото + ТЗ → `factory new` → правка брифа → `plan` → `run --mode live --allow-spend X`.
- Claude Code — основная среда разработки и эксплуатации: `CLAUDE.md` с правилами (деньги, ключи, спецификации),
  сабагенты `brief-writer` и `judge`, судья работает через headless Claude Code по подписке.
- Пропущенный судьёй брак → правило в память или признак в словарь; в конце недели — `factory weekly` в `results/weekly/`.

## Ограничения и что дальше
- Браков в реальной выборке всего 2: финалы уже прошли ручной отбор. Отбракованные черновики будущих заказов сохраняются для замеров.
- Правило двух сигналов проверено на тех же данных, по которым придумано. Нужен независимый замер на новых кадрах (M4).
- Перегенерация по замечаниям QC монтажа и видео пока не автоматическая: дорого, решение за человеком.
- Цели M4 к 31.12.2026: ≥ 20 live-прогонов, ≥ 300 кадров, ≥ 5 товаров или клиентов, еженедельные отчёты.
