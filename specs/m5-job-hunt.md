# M5 — агент поиска удалённой работы (`factory jobs scan`)

Статус: **работает** (02.11.2026): 15 тестов, первый реальный скан — `CASE.md`. Дальше: замер судьи на ручной разметке лидов.

## Цель
Тот же агентный конвейер, что и для визуала, но на входе — публичные ленты вакансий, а на выходе — дайджест
подходящих платных удалёнок с готовыми письмами. Ежедневный скан вместо ручного листания каналов и бирж.

```
источники (GET) ─► нормализация ─► дедуп по URL (журнал) ─► фильтр-агент (YAML-правила)
   ─► судья Claude: соответствие 1–5 + причина ─► автор писем RU/EN ─► проверка тона ──retry──┘
   ─► журнал leads.jsonl (append-only) + дайджест job_search/leads_digest_YYYY-MM-DD.md
```

## Границы (жёстко)
- **Только исследование и черновики.** Система никогда не отправляет сообщения, не заполняет формы, не создаёт
  аккаунты и не логинится. Отклик делает человек (или основная сессия) по ссылке из дайджеста.
- Только публичные ленты без авторизации: веб-превью Telegram `t.me/s/<канал>`, RemoteOK API, JSON-доски
  Greenhouse / Lever / Ashby, RSS WeWorkRemotely. Без обхода капчи и антибот-защиты.
- Никаких платных API: судья и автор писем — `claude -p` по подписке (расход лимита, не денег).
- Журнал и дайджест с чужими контактами — вне репозитория (`job_search/`), в git только код, правила и цифры.

## Конфиг `config/jobs.yaml`
Источники, профиль кандидата (навыки, кейсы с цифрами, ссылки), правила фильтра, порог судьи, лимиты.
Правило фильтра: `id`, `any: [regex]` — срабатывает при любом совпадении, или `all: [[regex], [regex]]` —
при совпадении в каждой группе (так записано правило «бесплатное тестовое, которое станет контентом их канала»).
